# SYSTEM SPECIFICATION: AUTONOMOUS ALPACA TRADING ENGINE
**Live Execution Rules, Risk Management & State Persistence (`paper_trader.py`)**

---

## 1. Operational Cadence & Data Ingestion

* **7-Bar Hourly Scan Schedule:** The daemon wakes up and scans the market exactly 7 times per day:
  * Bars 1-6: `10:30`, `11:30`, `12:30`, `13:30`, `14:30`, `15:30` EDT (Evaluating fully closed 60-minute candles).
  * Bar 7 (Pre-Close): `15:58` EDT (Pro-rates volume by `30/28` to capture end-of-day accumulation without waiting for the 16:00 close).
* **Instant Warmup:** Fetches a trailing 40-calendar-day window (~200 hourly bars) on every scan to ensure indicators (EMA 200, RSI 14, ATR 14) are fully stable at Bar 1 with zero startup lag.

---

## 2. State Persistence & Portfolio Governance

The script maintains a local `alpaca_state.json` file to give the algorithm memory between individual hourly scans.

* **Dynamic High-Water Mark (HWM):** 
  $$\text{HWM}_t = \max(\text{HWM}_{t-1}, \text{Current Account Equity}_t)$$
* **Drawdown Governor:** 
  * If the account drops $\ge 5\%$ from its HWM (`(HWM - Equity) / HWM >= 0.05`), the system enters **Defensive Mode**.
  * **Action:** Aggressive risk tiers (normally `2.0%`) are hard-capped at `1.0%` until the portfolio recovers.
* **Regime Burn Guard (`burned_regimes`):** 
  * Tracks the unique integer ID (`L_ID`) of the current oversold dip wave.
  * If a trade is executed, that `L_ID` is saved. If the trade hits its stop loss, the system **will not re-enter** that specific stock until a completely new dip cycle begins.

---

## 3. Position Sizing & Liquidity Limits

Position sizing is mathematically calculated using a virtual sizing base, with an overriding live-equity ceiling guardrail.

* **Dollar Risk Budget:** $\text{sizing\_risk\_base} \times \text{risk\_tier}$ (e.g., $\$30,000 \times 2\% = \$600$)
* **Base Share Calculation:** $\text{Shares} = \text{floor}(\text{Dollar Risk} / |\text{Entry Price} - \text{Stop Loss}|)$
* **20% Max Notional Cap:** Prevents tight stop losses from over-allocating buying power. 
  * $\text{Max Allowed Shares} = \text{floor}((\text{Current Equity} \times 0.20) / \text{Entry Price})$
  * The final share count is the *minimum* of the Base Share Calculation and the Notional Cap.
* **Position Ceiling:** Rejects new entries if `len(open_positions) >= max_positions` (Default: 15).
* **Duplicate Guard:** Skips any ticker already present in the active Alpaca portfolio.

## 4. AI Oracle Gatekeeper (`IE_Oracle_v6.0_Hourly`)

Every valid technical setup compiles an 8-feature array and queries the Machine Learning model before an order is placed:

1. `RSI_Extreme_Value`
2. `Dist_From_EMA_%`
3. `Entry_RVOL`
4. `Entry_ATR`
5. `Days_To_Earnings`
6. `Days_Since_Earnings`
7. `Entry_Month`
8. `Risk_Tier`

* **The Trap Veto:** If $P(\text{Trap}) \ge 0.35$ (35%), the trade is instantly aborted and logged as blocked.
* **The Whale Target:** If $P(\text{Whale}) > 0.42$ (42%), the system tags the trade metadata in `alpaca_state.json` to hold for an expanded **RSI 60** exit target. Default fallback is **RSI 50**.

---

## 5. Technical Entry Rules

A market buy order is submitted only when all conditions align:

1. **Macro Trend:** $\text{Hourly Close} > \text{EMA}_{200}$
2. **Setup State Armed:** 
   * **Aggressive Tier:** $\text{RSI}_{14} < 30$ (Applies `2.0%` risk).
   * **Tier 1:** $\text{RSI}_{14} < 35$ (Applies `0.5%` risk).
3. **Timing Hook 1 (RSI):** The RSI hooked up over the last 3 bars ($\text{RSI}_t > \text{RSI}_{t-1}$ AND $\text{RSI}_{t-1} \le \text{RSI}_{t-2}$).
4. **Timing Hook 2 (MACD):** The fast MACD line hooked up on the current bar.

---

## 6. Exit & Take-Profit Rules

* **Stop Loss (Alpaca Server-Side):** 
  * Price: $\text{floor}(\text{Lowest low reached while in the active dip state})$.
  * Submitted as a bracket OTO (One-Triggers-Other) order attached to the initial Market Buy. Resides securely on Alpaca's matching engine.
* **Take-Profit (Local Python Monitor):** 
  * At the start of every hourly scan, the script evaluates all open positions.
  * If a standard trade's current RSI crosses $\ge 50$, a `close_position()` market sell is fired.
  * If a Whale trade's current RSI crosses $\ge 60$, a `close_position()` market sell is fired.

---

## 7. Interactive Radar Heat Matrix

At the bottom of every hourly log, a live console radar prints the Top 10 most oversold candidates currently setting up.
* **Filter Gate:** Ticker must be $> \text{EMA}_{200}$ and $\text{RSI}_{14} \le 48$.
* **Sorting:** Ranked strictly by lowest RSI ascending (deepest dips at the top).
* **Display:** Shows Price, RSI, RSI Slope, MACD Slope, MACD vs Signal position, Distance from 200 EMA (%), and a clickable TradingView chart URL.
